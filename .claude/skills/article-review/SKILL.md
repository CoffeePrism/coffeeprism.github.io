# 文章审核（Coffee Prism）

站内大部分文章由每日生成器写成。旧版提示词要求模型写「有来源的数字」和专家引语却不给来源，所以 765 篇里约 90% 含有无法核实的内容（`scripts/content_checks.py` 可以查出来）。修旧文按下面的顺序做。

## 1. 先查重复

- 用标题和主题词搜 `content/posts/`：同一主题往往有 5–10 篇（例如「咖啡因」有 27 篇）。
- 同主题的一组文章合并成一篇：保留 Bing 流量最高的网址（看 `data/repair_priority.txt` 或 Bing Webmaster Tools 页面报告），其余文件删除，把它们的网址加进保留文章的 `aliases`，并把站内指向旧网址的链接改成新网址。范例：PR #5（咖啡因摄入量，合并 8 篇）。

## 2. 每个说法都要有来源

- 健康、安全类内容只用权威机构的资料（如欧洲食品安全局、美国 FDA、加拿大卫生部、英国 NHS、美国农业部食物成分数据库），文末列出来源和核对日期。
- 打开来源核对原文里的数字、单位、适用人群；不同机构说法不一时如实列出，给出更稳妥的建议。
- 找不到来源的数字、研究、报告、引语、价格和「我们实测」一律删除，不要换成别的数字。
- 冲煮参数可以用常见范围（如水温 90–96°C、粉水比 1:15 左右），说明是起点、要按口味调整。

## 3. 写法

- 第一段直接回答读者的问题；每个 H2 开头先给结论。
- 删掉 AI 腔：「不是……而是……」「值得注意的是」「总而言之」「让我们……吧」「在当今……时代」「解锁」「密码」「终极指南」等。读起来已经自然的句子不要动。
- 不要「要点速览」「总结」这类模板章节，除非真的有用；不滥用加粗。

## 4. 检查和提交

- 运行 `python3 -m unittest tests/test_content_checks.py`，并对改过的文章跑 `content_checks.findings(...)`，结果应为空（本站导读和电子书链接已豁免）。
- `hugo --minify --themesDir ./themes` 构建通过，旧网址的跳转页存在。
- 提交说明写清楚删了什么、来源是什么；部署用 `gh workflow run auto_publish.yml -f generate=false`。
- 批量删改用 `scripts/repair_posts.py`：它只删改被标出的句子，不允许新增数字，不合格就不改。先 `--dry-run`，再小批量运行并逐篇看 diff。
